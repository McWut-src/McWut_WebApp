# Area: Games (`/games`)

Load this before touching anything under `Pages/Games/`, `Controllers/GamesController.cs`, `wwwroot/js/games*.js`, or `GameScoreService.cs`. Rules unique to this area; shared rules are in `docs/AGENT.md`.

## What it is
A single-player browser arcade hub where signed-in members play standalone JS games — currently featuring **Stack 3D** (`stack-3d`, Three.js isometric slab stacker), **Mini Crossword** (`mini-crossword`, responsive 5×5 crossword pack with on-screen QWERTY keyboard, pencil mode, hints, check, and clean-word combo scoring), **Minesweeper** (`minesweeper`, Canvas 2D neon minefield with tap/long-press touch controls, cascade combos, and first-click safety), **Neon Slope** (`neon-slope`, Three.js 3D downhill runner with procedural curved track, obstacles, collectable gems, jump physics, and 2D canvas fallback), **2048 Neon** (`merge-2048`, reactive 4×4 number merging grid with smooth animations, synthesized chord audio, undo support, and mobile touch D-pad/swipe), **Wacky Wheels** (`wacky-wheels`, family-friendly Canvas 2D ragdoll physics stunt buggy obstacle course), **Cyber Breakout** (`brick-breaker`, neon synthwave brick-breaker with multiballs, lasers, and explosive power-ups), **Hextris Neon** (`hextris`, fast-paced hexagonal match-3 puzzle with spring rotation, cascading combos, and explosive particle clears), **Meme Merge** (`meme-merge`, Suika-style 2D physics puzzle with color gradient tiers from Skull up to The Rock Side Eye and synthesized Vine Boom audio), **Godzilla Rampage** (`godzilla-rampage`, Three.js 3D voxel pixel-art city destruction game — with automatic 2.5D Canvas fallback — starring a kid-crafted mossy orb-kaiju rescuing Baby Bronny James atop the Bronny Mega Tower), and **Subway Surfer** (`subway-surfer`, Three.js 3D endless runner — with automatic 2.5D Canvas fallback — featuring 3-lane rail dodging, oncoming and ramp-top express trains, side-scrape Inspector + Hound chase, hoverboard crash shield, Jetpack/Magnet/Sneakers powerups, and near-miss/roof-hop streaks) — and compete on a global high-score leaderboard.

## Golden Rules for All Games
1. **HTML / JS Standalone:** Pure single-player client-side execution. Zero server-side game simulation; the browser runs the complete game loop locally.
2. **Global Leaderboard Required:** Every game must integrate with the shared leaderboard (`GET /api/games/{key}/leaderboard` and `POST /api/games/{key}/scores`), tracking personal best scores, combo streaks, and total games played, while displaying member profile flair (display name, accent color pill, emblem badge, and status tag).
3. **Lightweight JS Engines & Vendors:** Games can use Three.js (`wwwroot/lib/three/three.min.js`), Alpine.js, HTML5 2D Canvas, or other lightweight JS vendors. All libraries must be vendored locally in `wwwroot/lib/` (no runtime external CDN calls). 3D/WebGL games must provide an automatic fallback (e.g., 2D isometric projection) for headless/restricted browsers.
4. **Mobile & Tablet Playable:** Every game must be responsive and fully playable via touch on phones and tablets (tap, swipe, touch-drag) as well as keyboard/mouse (Spacebar, Arrows, Click) on desktop. Viewports must resize dynamically across breakpoints (e.g., 390×844 to 1280×900).

## Behavior rules
- **Landing Page & Hub Architecture**: Direct visits to `/games` display the dedicated **Game Hub Landing Page** (`#game-hub-view`) with mobile-first, icon-first 2-column tiles (`.game-tile`) displaying large custom SVG icons, game titles, corner badges (`NEW`, `SOON`), and personal best pills (`[data-best-for]`, populated via `GET /api/games/me/bests`), with zero text bloat. Below the grid, the **Arcade Hall of Fame** card (`#hub-hall-card`) presents a horizontal snap-scrolling strip of game-selection chips (`.game-hall-chip` with `[data-hall-game]`) and high-score previews.
- **Stage Navigation & URL Routing**:
  - Direct visit `/games` -> `#game-hub-view` is visible; `#game-stage-view` is hidden; running game loops idle without physics/rendering load.
  - Clicking any catalog tile or "Play" button switches to `#game-stage-view`, activates the selected game, updates the URL to `/games?game={gameKey}` via `history.pushState`, and reveals the `All Games` back buttons (`#btn-back-to-hub` in header, `#btn-stage-back` in stage nav bar). On mobile screens (< 576px), back buttons collapse to icon-only and the stage switcher (`.game-hub-strip`) condenses to a horizontal icon-scroll bar saving ~250px of vertical height.
  - Tapping unreleased or "SOON" games surfaces a non-blocking `mcwut.toast` alert without navigating into an empty stage.
  - Clicking `All Games` returns to `#game-hub-view`, resets the URL to `/games`, and pauses running timers/loops.
  - Deep-linking (`/games?game=stack-3d`, `/games?game=neon-slope`, etc.) opens directly into the requested game stage without intermediate hub flashing.
  - Browser back/forward navigation (`popstate`) seamlessly switches between the Hub landing page and individual game stages.
- Each member has one leaderboard record per `GameKey` (`GameScores` table, unique index on `(GameKey, UserId)`), tracking `BestScore`, `BestCombo`, `GamesPlayed`, `AchievedAt`, and `LastPlayedAt`.
- Submitting a score increments `GamesPlayed`, updates `BestCombo` if higher, and replaces `BestScore` + `AchievedAt` only when the new score beats the player's previous record.
- Leaderboard rows sort in memory (`BestScore` descending, then `BestCombo` descending, then earlier `AchievedAt` ascending) because SQLite cannot `ORDER BY` a `DateTimeOffset`.
- Player rows render the member's `DisplayName` (resolved via `MemberLabel.Shown`), profile `AccentColor` pill (`#0b1f3a` fallback), optional `HeaderBadge` emblem, and `StatusTag`.
- Three.js is vendored locally at `wwwroot/lib/three/three.min.js`. `wwwroot/js/games-stack3d.js`, `wwwroot/js/games-neon-slope.js`, `wwwroot/js/games-godzilla.js`, and `wwwroot/js/games-subway-surfer.js` use `THREE.WebGLRenderer` with automatic 2D isometric/perspective canvas projection fallbacks if WebGL context creation is unavailable on a headless or restricted device.

Camera & coordinate rule: The Three.js camera looks down +Z from behind the ball (`z = ball.z - 6.8` looking towards `z = ball.z + 16.0`), so in Three.js right-handed coordinates world +X projects to screen-left and world -X projects to screen-right. The 2D canvas fallback projects screen X as `sx = width / 2 - (x - camX) * scale` to preserve exact coordinate parity between 3D and 2D fallback modes.

## Endpoints / files
- `GET /api/games` returns the game catalog (`GameScoreRules.Catalog`).
- `GET /api/games/me/bests` returns a dictionary mapping `gameKey` to the signed-in player's personal best score.
- `GET /api/games/{gameKey}/leaderboard` returns `GameLeaderboardView` (top players + signed-in player's record and rank).
- `POST /api/games/{gameKey}/scores` submits `{ score, maxCombo }` and returns `GameScoreSubmissionView`.
- `GET /api/games/{gameKey}/levels`, `GET /api/games/{gameKey}/levels/{id}`, `POST /api/games/{gameKey}/levels`, `PUT /api/games/{gameKey}/levels/{id}`, `DELETE /api/games/{gameKey}/levels/{id}`, and `POST /api/games/{gameKey}/levels/{id}/runs` manage member-created custom levels and course records (`GameLevelRules` and `GameCustomLevelService`).
- Rules live in `GameScoreRules` and `GameLevelRules` (`src/FamilyVault.Files/Security/`); services are `GameScoreService` and `GameCustomLevelService` (`src/FamilyVault.Files/Services/`).
